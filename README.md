# Trading Agent: وكيل تداول بالذكاء الاصطناعي (MT5 Demo)

وكيل Claude مستقل يحلل الأسواق ويقرر بنفسه: أي سوق، اتجاه الصفقة، وقف الخسارة، الهدف، المخاطرة، ومتى لا يتداول.
يعمل على **حساب MetaTrader 5 تجريبي** وعلى **محاكي backtest** بالكود نفسه.

> مشروع بحثي على أموال وهمية. لا شيء هنا نصيحة استثمارية، ونجاح الحساب التجريبي لا يضمن أي نتيجة حقيقية.

## الفكرة

```
            ┌──────────────────────────────┐
            │   Claude (Opus 5.5) Agent    │  يُستدعى عند إغلاق كل شمعة قرار (H1 افتراضيًا)
            │  يحلل ← يقرر ← يكتب أسبابه    │
            └──────────────┬───────────────┘
                           │ أدوات (tools)
   ┌────────────┬──────────┼───────────┬──────────────┐
   ▼            ▼          ▼           ▼              ▼
 السوق      الشموع     الحساب     فتح/تعديل/      السجل والدروس
 overview  +مؤشرات    والمخاطر    إغلاق صفقة       (ذاكرة دائمة)
                           │
                  ┌────────▼────────┐
                  │  Risk Manager   │  حدود ثابتة في الكود لا يستطيع الوكيل تجاوزها
                  └────────┬────────┘
              ┌────────────┴────────────┐
              ▼                         ▼
        SimBroker (backtest)      MT5Broker (demo)
```

**أهم المبادئ في التصميم:**
- **حدود المخاطر في الكود وليست في التعليمات:** وقف خسارة إجباري، والوقف يُشدَّد فقط ولا يُوسَّع، وحد مخاطرة لكل صفقة (1%) ولمجموع الصفقات المفتوحة (3%)، وحد خسارة يومي (3%)، وحد أدنى لنسبة الربح إلى المخاطرة، وفلتر للـ spread.
- **الهدف اليومي معلومة وليس إلزامًا.** يوم بلا صفقات نتيجة مقبولة.
- **كل دورة محادثة جديدة.** ذاكرة الوكيل هي سجل الصفقات وملاحظاته المحفوظة (`save_note`)، فلا يتضخم السياق ولا يتراكم الخطأ.
- **مراجعة يومية:** في نهاية كل يوم يراجع الوكيل صفقاته ويحفظ الدروس المدعومة بالأدلة فقط.
- **وكيل عشوائي للمقارنة** (`--agent random`): نفس المخاطر والتكاليف بلا أي مهارة. إذا لم يتفوق Claude عليه بفرق ذي دلالة إحصائية، فلا توجد أفضلية.
- **لا تسرّب للمستقبل في الـ backtest:**
  - الوكيل يرى الشموع المكتملة فقط.
  - التنفيذ على افتتاح الشمعة التالية مع الـ spread.
  - إذا لمست الشمعة الوقف والهدف معًا، يُحتسب الوقف.
  - **التواريخ مخفية** (يرى "Tue 14:00" فقط)، حتى لا يستخدم النموذج ذاكرته عن أحداث تاريخية.
  - البحث في الويب معطّل دائمًا في الـ backtest.

## التثبيت

```bash
pip install -r requirements.txt
cp config.example.yaml config.yaml          # ثم عدّل الإعدادات
export ANTHROPIC_API_KEY=...                # مفتاح Claude API
```

الربط المباشر مع MT5 يتطلب **Windows** (مكتبة `MetaTrader5` تعمل على Windows فقط)، مع منصة MT5 مثبتة ومسجّل فيها الدخول بحساب Demo.

```powershell
setx MT5_LOGIN 12345678
setx MT5_PASSWORD "your-demo-password"
setx MT5_SERVER "YourBroker-Demo"
```

**أمان:** البوت يرفض العمل على حساب حقيقي إلا إذا غيّرت `allow_real_account` في الإعدادات. ويدير فقط الصفقات التي تحمل رقم الـ magic الخاص به.

## الاستخدام

### 1. تجربة سريعة بدون بيانات حقيقية (أي نظام تشغيل)
```bash
python -m trading_agent sample-data --days 120          # بيانات عشوائية تمامًا لاختبار النظام فقط
python -m trading_agent backtest --agent random --random-p 0.3 --seed 1
```
على بيانات عشوائية، أي وكيل يجب أن يخرج بلا أفضلية تقريبًا ويخسر قليلًا بسبب التكاليف. هذا اختبار سلامة للمحاكي نفسه.

### 2. تحميل بيانات تاريخية حقيقية من MT5 (على Windows)
```bash
python -m trading_agent download --timeframe M15 --bars 100000
```
البديل: صدّر الشموع يدويًا من MT5 (View ← Symbols ← Bars ← Export) واحفظها باسم `data/EURUSD_M15.csv`.
حمّل سنة على الأقل قبل بداية الاختبار، لأن مؤشر EMA200 على الإطار اليومي يحتاج 200 يوم من التاريخ.

### 3. Backtest للوكيل الذكي
```bash
python -m trading_agent backtest --agent claude --max-cycles 50 --label "first-try"
python -m trading_agent backtest --agent random --seed 1 --label "baseline"
python -m trading_agent report
```

### 4. تشغيل مباشر على الحساب التجريبي (Windows)
```bash
python -m trading_agent live --agent claude -v
```
للإيقاف الآمن أنشئ ملفًا باسم `STOP` في نفس المجلد، أو اضغط Ctrl+C.
فعّل `agent.web_search: true` إذا أردت أن يقرأ الوكيل الأخبار والأجندة الاقتصادية في التشغيل المباشر.

## التكلفة

كل دورة قرار تستدعي Claude مرة أو أكثر (الوكيل يطلب الشموع ويحلل ثم يقرر):
- دورة بلا صفقة: غالبًا 2–5 استدعاءات.
- إطار H1 على 4 أزواج: حوالي 120 دورة أسبوعيًا.
- للتقليل: `--max-cycles`، أو `decision_timeframe: H4`، أو `effort: medium`.
- الـ system prompt والأدوات عليها prompt caching، فالجزء الثابت يُحسب بعُشر السعر.
- استهلاك الـ tokens يُسجَّل لكل دورة ويظهر في `report`.

## كيف تحكم على النتائج

| السؤال | الأداة |
|---|---|
| هل متوسط R أكبر من صفر بدلالة إحصائية؟ | `t_stat_avg_r` و `p_value_edge` في التقرير |
| هل يتفوق على العشوائي بنفس التكاليف؟ | backtest لـ `random` بعدد صفقات قريب |
| هل النتيجة ليست صدفة فترة معينة؟ | اختبر فترات مختلفة لم تُستخدم في تعديل الـ prompt |
| هل تستمر مباشرة؟ | شغّل Demo لأسابيع وقارن |

قاعدة تقريبية: أقل من 200 صفقة لا تكفي لأي حكم قوي. وإذا عدّلت الـ prompt بعد كل اختبار، فاحتفظ بفترة بيانات أخيرة لا تختبر عليها إلا مرة واحدة في النهاية.

## هيكل المشروع

```
trading_agent/
  agent/claude_agent.py   حلقة Claude (tool use، adaptive thinking، caching، refusal fallback)
  agent/tools.py          أدوات الوكيل وتنفيذها
  agent/prompts.py        الـ system prompt ورسائل الدورات والمراجعة
  agent/random_agent.py   الوكيل العشوائي للمقارنة
  broker/simulated.py     محاكي backtest بلا تسرّب للمستقبل
  broker/mt5.py           الربط مع MetaTrader 5
  risk.py                 مدير المخاطر (حدود ثابتة)
  journal.py              سجل SQLite لكل صفقة وقرار وملاحظة
  market.py, indicators.py  تجهيز البيانات والمؤشرات
  stats.py                الإحصاءات واختبار الدلالة
  runner.py, __main__.py  التشغيل وسطر الأوامر
tests/                    اختبارات المحاكي والمخاطر وحلقة الوكيل
```
